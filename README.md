# apps-wss-test

Тестовый WebSocket echo-сервер для проверки WSS в Timeweb Cloud Apps.
Написан на Deno, внешних зависимостей нет.

## Деплой в Apps

Рекомендуемый вариант — деплой из Dockerfile:

1. Подключить этот репозиторий, ветка `main`.
2. Выбрать деплой из `Dockerfile` в корне репозитория.
3. Корень проекта — корень репозитория. Дополнительные команды сборки и запуска не нужны.
4. Приложение слушает `0.0.0.0:8000`, порт объявлен в Dockerfile.
5. Если включена проверка состояния, указать путь `/health`.
6. После деплоя проверить `https://<домен>/health`.

Альтернатива — Deno без фреймворка: версия `2.7.14`, точка входа `main.ts`,
команда запуска `deno run --allow-net --allow-env=PORT main.ts`.
Установка зависимостей не требуется. `PORT` по умолчанию равен `8000`.

## Endpoint'ы

- `/` — название и версия тестового сервера.
- `/health` — JSON со временем старта процесса, версией Deno и счётчиками.
- `/ws` — WebSocket echo; текст и бинарные сообщения возвращаются без изменения.
  Адрес подключения снаружи: `wss://<домен>/ws`.
  Обычный HTTP-запрос без WebSocket Upgrade возвращает `426`.

Сервер сам не отправляет heartbeat; `idleTimeout: 0` отключает встроенный
idle ping/timeout Deno. В коде не заданы квоты соединений, сообщений или
длительности сессии. Для активного теста heartbeat отправляет клиент.
Другие ограничения Deno, ОС и платформы этим не отменяются.

## Как интерпретировать измерения

`/health` показывает `activeConnections`, `totalConnections`, `messagesReceived`,
`bytesReceived`, `bytesSent`. Счётчики сбрасываются при перезапуске процесса;
`startedAt` помогает его заметить. Байты считаются по полезной нагрузке
сообщений, без WebSocket/TLS/TCP-заголовков. `bytesSent` — объём переданного
в `socket.send()`; это не подтверждение доставки клиенту. Доставку, задержки
и пропуски проверяет клиент. Счётчики относятся к одному процессу.

Проверять отдельно: простой без сообщений, активную длительную сессию,
одновременные соединения, сообщения в секунду и объём переданных данных.
Нагрузочный клиент запускать с другой машины. Фиксировать CPU/RAM App,
версию сервера, длительность и параметры каждого прогона.

Echo-тест измеряет транспорт для конкретного App и конфигурации. Он не
заменяет тест игровой логики и рассылки сообщений между игроками и не
доказывает отсутствие любых платформенных лимитов.

## Статус проверки

До первого деплоя код не проверен запуском. Runtime-проверки и измерение
ограничений выполняются на тестовом App после деплоя.
